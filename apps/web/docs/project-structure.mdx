# Project Structure

The app splits cleanly into two halves under `src/`: **`server/`** runs only on the Bun process,
and **`web/`** is the React tree that runs on both the server (SSR) and the browser (hydration).
A small `types/`, `utils/`, and `workers/` round it out.

## The two halves

### `src/server` — the Bun process

Everything here runs only on the server and never ships to the browser.

| Path | Responsibility |
| --- | --- |
| `server.ts` | `Bun.serve()` entry — rate limiting + top-level error handling. |
| `router.ts` | Dispatches each request: BFF → REST proxy → GraphQL proxy → SSR. |
| `bff/` | The Backend-for-Frontend: aggregation handlers, proxy, typed clients, circuit breaker, cache. See [The BFF Layer](/architecture/bff). |
| `lib/handleRequest.ts` | Static-file serving and the SSR entry. |
| `lib/web/utils/render.tsx` | Streams the React app with `renderToReadableStream` and dehydrates the query cache. |
| `lib/prefetch.ts` | Per-route server prefetch that warms TanStack Query before render. |
| `lib/csrf.ts` | CSRF token generation and the `/bff/*` CSRF middleware. |

### `src/web` — the React tree

This runs in both environments. The same `App` component is rendered by the server and hydrated
by the browser entry.

| Path | Responsibility |
| --- | --- |
| `App.tsx` | Composes the provider stack (data layer → theme → auth → collection → deck → routes). |
| `browser/browser.tsx` | The client entry — `hydrateRoot` with a browser router. Built by `build.ts`. |
| `routes/` | The shared `react-router` route table and the runtime-aware `RouterLayer`. |
| `pages/` | One directory per route (`BrowsePage`, `DeckBuilderPage`, …). |
| `components/` | Reusable presentational + container components, each with its own folder. |
| `contexts/` | App-wide React contexts: `Auth`, `Deck`, `Collection`, `Theme`, `Toast`. |
| `hooks/` | Isomorphic TanStack Query hooks (`useSets`, `useCard`, …). |
| `services/` | HTTP client classes extending `APIModel` that call the proxied API. |
| `layers/data/` | The `DataLayer` that swaps the query client between server and browser runtimes. |
| `graphql/` | The GraphQL client, typed documents, and query hooks. |

### `src/workers`

`simulation.worker.ts` runs the headless game engine (`@pokemon/engine`) off the main thread for
the (feature-flagged) Simulate page. It is built as a separate entrypoint by `build.ts`.

## Path aliases

Imports inside `src/web` and the SSR render path use the `@/` alias (e.g.
`@/web/services`, `@/web/layers/data`), resolving to `src/`. Server-internal modules use relative
imports.
